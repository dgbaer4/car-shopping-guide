## Direct sharing and receipts

The shopper saves locally, reviews the proposed payload, gives consent, and continues to **Share Price**. A native HTTPS form POST carries one sanitized observation in the request body to the Google web app in the same tab. The hosted page validates and previews the handoff. The shopper enrolls once, then gives explicit consent and taps **Share Price**. Returning via browser Back preserves the tracker. The ordinary authorized flow requires no copy/paste or app account. The under-30-second interaction target still needs live timing on iPad.

Google's documented web-app `doPost` and HTML Service `google.script.run` support this handoff design. A top-level navigation avoids reliance on reading a cross-origin response from GitHub Pages, CORS preflights, or opaque requests. The RPC uses the hosted HTML Service bridge. The page never submits on arrival. A deliberate action while viewing the hosted page is required even when a token is remembered. The endpoint remains disabled in the default package pending verification of the deployment's sign-in policy, navigation, storage and private Sheet writes. [Google web apps](https://developers.google.com/apps-script/guides/web) · [Google browser RPC](https://developers.google.com/apps-script/guides/html/communication) · [Apps Script sandbox](https://developers.google.com/apps-script/guides/html/restrictions)

The server uses the stable observation UUID and canonical payload digest under a script lock. A verified write or matching retry returns that UUID and the original UTC receipt timestamp. A changed payload for an existing ID returns a conflict. The hosted page verifies the returned ID and receipt timestamp before displaying success. Failures, an unexpected receipt, and timeouts leave delivery unconfirmed. An unconfirmed submission can be retried with the same selected fields and ID. The local tracker remains usable without the enrollment service or after a failed handoff.

## Security and privacy

The owner generates a random familiar word and four digits with Web Crypto. The server compares an HMAC of the normalized invitation and limits guessing across all clients using the invitation. Eight attempts per UTC hour, 24 failed guesses per invitation, a 30-device issuance cap, and a seven-day invitation expiration bound online guesses. Shared limits can temporarily deny enrollment to legitimate testers during abuse. The owner can rotate the invitation or suspend intake. Google execution and storage quotas still apply.

Enrollment combines an owner-generated 256-bit key and a browser-generated 256-bit nonce with HMAC-SHA256 to produce a server-issued bearer secret. A separate device identifier allows revocation. The server retains a token digest, expiry and request counters in private Script Properties. Remembered authorization has a 30-day idle limit renewed by a successful submission or verified retry and a 90-day hard limit. Session authorization expires after 12 hours. The owner can revoke an individual device or pause enrollment and submissions globally. Authorized requests are capped at 20 per device per UTC hour, 10 new writes per device per UTC day and 50 new writes per UTC day across the pilot, with a 5,000-row raw capacity limit.

Browser storage is scoped to the Google-hosted page. Remembered authorization uses local storage and session mode uses tab storage. Safari and embedded Google frames can partition or reject storage, and device users with access to the same browser profile may have access to a retained token. If storage is unavailable, authorization remains in memory for the current page and a later handoff may require enrollment. Raw intake is private. The shared allowlist excludes local interest, notes and buyer-profile data. Optional details default off, query strings and fragments are removed from shared links, and owner privacy review remains required. The app writes neither observations nor credentials to GitHub, and representative market pricing is unaffected by contributions.
