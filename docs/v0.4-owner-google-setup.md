# Set up private pilot price collection

The Shopping Tracker works without Google services. Only configure shared intake after you are ready to test it with synthetic data. The default static build has no intake URL. The collection runs as a Google Apps Script web app with a private Google Sheet.

## 1. Prepare the private Google resources

On iPad, open Google Sheets and Apps Script in Safari. Use **Request Desktop Website** from Safari’s page menu if the editor or deployment controls are hidden. Use an owner-controlled Google account. A dedicated account with access only to the collection sheet is preferable because the script uses the spreadsheet authorization available to that account.

1. Create a Google spreadsheet for pilot intake. In **Share**, set **General access** to **Restricted**. Confirm that every listed person is an authorized reviewer. Copy the spreadsheet ID between `/d/` and `/edit` in its URL.
2. Create a private standalone project at [Apps Script](https://script.google.com/). Confirm that the project is using V8 in **Project Settings**. Keep project access restricted to trusted owners and editors, since editors can view configuration and affect intake.
3. Paste [Intake.gs](../collection/Intake.gs) into the default script file. Add a Script file named `ObservationValidation` and paste the [generated validator](../collection/ObservationValidation.gs). Add an HTML file named `Intake` and paste [Intake.html](../collection/Intake.html). Copy each file from this feature revision in GitHub or from the release integrator's package.
4. In **Project Settings → Script properties**, set `SPREADSHEET_ID` to the private spreadsheet ID and `INTAKE_OPEN` to `false`. In the editor's function picker select `initializeCollection_`, then tap **Run**. Grant spreadsheet access when Google prompts. If an editor does not list underscore-suffixed functions, add a temporary owner-only wrapper that calls `initializeCollection_`, run it privately, and remove it before any deployment.
5. Verify the `Raw_Observations`, `Reviewed_Observations`, `Rejected_Observations`, `Vehicle_Aliases`, `Processing_Log` and `Data_Dictionary` tabs. Keep the sheet link private. Verify from a separate, unauthorized Google account or signed-out Safari window that the spreadsheet URL asks for access. Confirm that no **Publish to web** setting is active.

## 2. Generate the key and first invitation

Open `owner-credentials.html` from a trusted HTTPS preview of the exact feature package. A local developer can also serve that package on localhost. The helper uses Web Crypto in the tab and has no network, persistence or account operations.

1. Tap **Generate a key for first setup**, then **Show or hide the token key**. Copy the field to a new private Script Property named `TOKEN_KEY`. Store the key securely for future invitation rotation.
2. Tap **Generate a seven-day invitation**. Copy the full settings value into the `INVITATION` Script Property. This is a JSON object with a keyed digest and an expiration. Distribute only the memorable invitation to the invited shopper, directly and privately. Keep the settings value and token key private.
3. Close the helper tab and clear the clipboard after copying secrets. Avoid putting an invitation, key, device token or private observation in a GitHub issue, screenshot, source file or log.

To rotate, paste the current `TOKEN_KEY` into the helper and generate a new invitation. Replace the `INVITATION` property and distribute the new code directly. Remove `INVITATION` if you need to close enrollment while keeping existing authorized devices active. Existing authorizations continue until expiry, revocation or intake suspension. Rotating the invitation resets enrollment limits for the new digest. Reserve token-key rotation for incidents. If secrets or bearer tokens may have leaked, suspend intake and remove or revoke the affected device records before resuming.

## 3. Deploy and verify

1. In Apps Script choose **Deploy → New deployment → Web app**. Set **Execute as** to the deploying owner. Use the narrowest **Who has access** policy that reaches the testers. Google sign-in may be required by the policy. The application itself collects no account, name, email or password for authorization. Use Google's signed-out **Anyone** access only when your policy and invitation-based pilot allow it. Review the difference between web app access and sheet sharing before proceeding.
2. Copy the deployment's HTTPS `https://script.google.com/macros/s/…/exec` URL. Use `/exec`, which serves a deployed version. An integrator can package an isolated preview with `python tools/build_recommendation_catalog.py --site /tmp/csg-live-test --intake-url "$csg_intake_url"`, where the variable is set to that public endpoint. Test the same HTTPS preview URL on iPad. This changes only the preview's endpoint configuration.
3. Verify the endpoint from a separate browser profile with the intended Google access policy. Opening it directly should show instructions to start from the Shopping Tracker. Set `INTAKE_OPEN` to `true` for the test window.
4. In the preview, record a synthetic vehicle and price. Save locally, choose **Share or export contribution**, review, consent and tap **Continue to Share Price**. Verify that the Google page receives the selected fields and URL contains no payload or credential. Enroll with a fresh invitation, select **Remember this device**, then give submission consent and tap **Share Price**.
5. Confirm that the hosted page displays **Received**, the observation ID and UTC receipt time. As owner, verify exactly one matching row in `Raw_Observations`. It should show consent `v2` and exclude private shopping notes, interest, buyer-profile data and any optional details the shopper left unchecked. Confirm that the representative pricing asset is unaffected.
6. Use Safari’s **Back** button to return to the tracker. Reopen the same observation, select the same fields and share again. Confirm that the remembered device skips enrollment and the receipt says **Already received** with the original timestamp. Verify the Sheet row count is unchanged. Repeat in a regular Safari tab, in Private Browsing, and with the intended Google sign-in policy. Test that a lost response is reported as unconfirmed and that retrying the original payload does not write twice.
7. Exercise revocation and suspension with the test device. Keep synthetic rows out of any publication batch. Set `INTAKE_OPEN` back to `false` at the end of the verification window. Record the outcome and any Safari or sign-in limitations before authorizing an endpoint for real pilot use.

When updating the script, replace all three matching files and create a new version under **Deploy → Manage deployments → Edit**. Keep the endpoint private until testers need it. Recheck the intended Google access policy and receipt flow after changing deployments. The public endpoint itself is not an authentication secret. [Google web app deployment](https://developers.google.com/apps-script/guides/web) · [Hosted browser RPC](https://developers.google.com/apps-script/guides/html/communication)

## 4. Revoke, suspend, and manage limits

- **Revoke one device.** Ask the tester for the **Device reference** shown in the hosted sharing form. In Script Properties add `REVOKED_<device-reference>` with value `true`. Delete the corresponding `DEVICE_<device-reference>` entry. Keep the revocation property until the token's maximum lifetime of 90 days has passed, then remove it during cleanup. A request accepted just before suspension or revocation can finish. Check the raw tab when investigating such a case.
- **Suspend all intake.** Set `INTAKE_OPEN` to `false` in Script Properties. The switch gates enrollment and submission. During suspected sustained abuse, also restrict or archive the deployment in **Manage deployments**. Resume only after checking the raw tab and reviewing access settings.
- **Manage renewals.** Remembered authorization renews for up to 30 days after a confirmed submission or identical retry, with a hard 90-day limit from enrollment. A tab-session authorization expires after 12 hours. Expired or revoked devices must enroll again with a currently valid invitation. Browser **Forget this device** removes the local credential. Use server revocation to invalidate an existing copy of the bearer token.
- **Watch capacity.** Enrollment permits eight attempts per UTC hour, 24 failed attempts and 30 device issuances per invitation. A blocked invitation needs owner rotation. An authorized device can make 20 submission attempts per UTC hour and write 10 new rows per UTC day. Intake allows 50 new rows per UTC day and up to 5,000 raw rows. Clean out expired device properties after their absolute expiry. Google service quotas can be reached before application limits during a traffic flood. [Apps Script quotas](https://developers.google.com/apps-script/guides/services/quotas)

The hosted page stores authorization in its own browser storage. Remembered mode uses local storage and tab mode uses session storage. Safari can partition, block or evict both. Anyone with access to the browser profile could use a retained token. Choose tab mode on shared devices and keep private tracker backups secure. When storage is blocked, the current hosted page can still submit after enrollment. A subsequent handoff may ask to enroll again. If account policy or Safari prevents POST handoff or a verified receipt, keep shared intake disabled for that audience and use the sanitized export with a private owner-approved transfer path. Preserve the local observation and its ID. [Apps Script HTML sandbox](https://developers.google.com/apps-script/guides/html/restrictions)
